01 / Recommendation

Decision: integrate a DAW engine, not a pile of audio primitives

Use Tauri + Rust for the application platform and a Tracktion Engine + JUCE C++ worker for musical state and audio. Add specialist libraries only when a specific engine gap is demonstrated. Keep React/TypeScript for presentation, not authoritative project data or audio buffers.

Recommendation is conditional, not a completed migration

Pass a small native integration proof and settle distribution rights before locking the engine. “Open source” does not mean permissive, actively maintained, or compatible with every business model.

Rust addresses the platform concern, not every memory problem. Use bounded caches, bounded worker queues, streamed assets and explicit ownership. C++ plugins, inference tensors, GPU textures and WebView objects can still exhaust memory. Avoid promising a footprint reduction until the same session is measured on target hardware.

02 / Build versus integrate

Capability boundary: what the engine saves, and what it does not

Capability familyReuse firstVOID integration or remaining gap
Musical session and timelineEngine Edit, tracks, clips, tempo map, MIDI data and save/load.Object-ID contract, command adapter, arrangement UI and recovery coordination.
Record, play, route and renderExisting engine/device/routing/render functions.Device UX, monitoring policies, export options, fixtures and physical latency tests.
Automation, history and selectionEngine automation, undo/redo, selection utilities and parameter mapping.One user-facing history for mixed audio/visual operations, gesture edits and AI approval.
Instruments and pluginsStarter synth/sampler/effects and native plugin hosting.Curated sound content, instrument UX, compatibility database and robust crash behavior.
Logic-level specialist depthReuse specialist components where suitable.Vocal pitch-editing workflow, advanced notation editing, calibrated mastering, spatial delivery and exact interchange still require dedicated work.
tefeaturesteproduct
Do not count an SDK capability as a shipped VOID workflow

A native API for recording does not provide the track-arming UI, failure recovery, monitoring policy, comping journey or accessibility behavior. The integration acceptance tests must cover that complete path.

Tracktion supplies no complete studio interface. Do not plan to drop in Waveform’s proprietary application UI. Native plugin processing isolation is also a separate requirement: a scanner subprocess protects scanning, not a running plugin inside the engine process.

05 / Proposed architecture

ADR refinement: one musical truth, separate native workers

This refines the earlier Rust-first ADR. Rust remains the main application and orchestration layer. To maximize engine reuse, it should not also maintain a competing mutable song graph or a second audio undo stack. This ownership decision must be recorded before implementation.

Command and save contract

Every editing command carries commandId, projectId, expectedRevision, operation type and validated parameters. Acknowledgements return the committed revision plus a bounded delta. Repeated IDs must not create duplicate clips. Stale AI proposals must be rejected or explicitly rebased.

For a save, write an engine snapshot and visual metadata against the same coordinated revision into a new checkpoint directory. Flush and hash those files, then atomically publish the manifest pointer; use the database transaction as the durable coordinator record. Retain the previous verified checkpoint. Recover incomplete staging writes instead of trusting timestamps. This is a designed multi-file protocol—not a free cross-file SQLite transaction.

Use Tracktion’s native undo for musical changes. The controller exposes one user-visible command history and coordinates companion visual/asset operations. Define cross-domain undo transactions and recovery semantics explicitly; do not maintain two unrelated Ctrl-Z stacks.

Real-time and process rules

Audio/MIDI remain native. Commands are applied off the audio callback and handed to the playback graph through bounded native mechanisms. The callback must not wait on UI IPC, SQLite, downloads, logs, model inference or general async tasks. Native plugin isolation may use shared PCM buffers, but that transport is not the WebView command channel. Account for bridge buffering in delay compensation.

A separate engine process avoids forcing Tauri and JUCE to share one platform UI loop. Begin with plugin editors in native top-level windows. Prove focus, resize, DPI, keyboard routing and teardown on each OS before attempting embedded editors. Engine-process separation protects the shell from an engine crash; it does not guarantee uninterrupted audio if a plugin crashes in that engine.

11 / Kickoff constraints

What the implementation agent should do first

Record the accepted Tauri/Rust/C++ direction and this proposed engine-ownership refinement. Create a dependency register from the catalog, but mark every package unqualified until its gate passes. Resolve engine and JUCE distribution rights before expanding the implementation. Build the smallest native worker proof using official examples, not a custom replacement engine.

Define the protocol, command IDs, revision behavior, error model, lifetime ownership and checkpoint format. Then implement one vertical path: create project → add track/clip → play → open native plugin UI → edit → save → close → reopen → render. Add recording next. Fail the phase if it only renders a UI or reports successful stub methods.

Keep engine, model and visual adapters replaceable through narrow contracts. Prefer an upstream fix or a small reviewed adapter over a permanent fork. Document any fork owner and upgrade plan. Do not claim Logic parity from a dependency’s README; report completed user workflows and test evidence.

Scope and confidence

Research checked primary project/vendor documentation and public repository material as available on 7 October 2026. Components were not compiled, benchmarked, security-audited or integrated into VOID in this task. No repository changes were made. Exact supported-version locks, hardware requirements, licence procurement and model-quality decisions remain qualification work.
