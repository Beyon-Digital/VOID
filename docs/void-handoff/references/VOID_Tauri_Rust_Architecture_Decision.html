01 / DECISION

Change the shell recommendation—not the product goals.

Use Tauri + Rust + React/TypeScript. Do not interpret this as “rewrite every dependency in Rust.”

The audited desktop is a small shell and the audio adapter is mostly unimplemented. This makes a shell change more reasonable now than after completing recording, recovery and plugin integration. [R1] [R2] [R5] This is a planning conclusion, not a measured migration estimate.

Replace

Electron lifecycle, preload and IPC with Tauri and narrowly scoped Rust commands.

Keep

React UI, useful design tokens and components, TypeScript for editor interaction and presentation.

Build natively

Document validation, scheduling, audio processing, storage, hardware I/O and worker supervision.

Tauri uses system WebViews instead of bundling its own browser engine. This changes shell distribution overhead, but does not establish a performance or memory saving for the complete studio. Measure the process tree, model memory and project load—not an empty-window comparison. [S1]

Electron can also run heavy work outside its UI process. The strongest performance decision is native audio separated from UI and AI; Tauri is the recommended shell around that architecture, not its real-time guarantee. [S2] [S12]

Scope of this revision: replace the prior “retain Electron” recommendation. Preserve manual studio operation, editable AI proposals, the audio-first clock and all parity requirements. This document does not mark any code as migrated.

03 / CONTRACTS

Different workloads need different paths.

TrafficProposed pathRequired behavior
Edits / undo / project accessTyped frontend → Rust commands.Command ID, project revision, validated payload, success/error result. Reject stale AI proposals or require rebase.
Meters / playhead / progressRate-limited channels or compact snapshots.Drop superseded telemetry under load. Never slow audio because a view is hidden or busy.

Physical MIDI / live controllersNative input with source timestamps.Convert timestamps into the audio clock domain. Do not route external MIDI through a DOM event loop.
Touch / pointer gesturesLocal interaction feedback + timestamped, coalesced intent to the native engine.Smooth continuous parameters. Keep note-off and panic reliable; UI delivery is not promised to be sample accurate.
AI outputWorker → proposal/asset → validation → audition → acceptance.Generate ahead. Missed deadlines skip a suggestion; they never interrupt playback. Accepted content uses ordinary project primitives.
VisualsNative output follows clock snapshots; preview uses its own rate budget.Allow visual frame drops before sacrificing audio. Pre-render expensive generative material for live performance.

Tauri documents its event bus as unsuitable for low-latency or high-throughput work; channels are the streaming mechanism. Neither is a real-time audio callback transport. [S3]

Callback contract: preallocate; bound execution; do not block on locks, files, network, UI, models or GPU work. Build replacement graphs off-thread and reclaim old state off-thread. A lock-free label alone does not prove bounded execution. [S5]

Rust removes reliance on a tracing garbage collector in native Rust code. That does not prevent allocation, blocking, expensive destructors, unsafe FFI or missed deadlines. The web UI still has its own JavaScript runtime. [S4] [S1] Hardware, drivers and workload must be qualified separately.

04 / TRADE-OFFS

Rust-first, not Rust-only.

OptionUseful advantageMain costDecision
Tauri + Rust + thin web UINative platform ownership and a system-WebView shell.OS-specific WebView behavior; native surfaces and plugin windows require validation.Recommended for this scaffold.
Electron + the same native engineKnown Chromium baseline; can preserve an established shell.Bundled browser runtime; still needs the native engine and isolation work.Valid fallback if Tauri fails a required integration gate.
Pure-Rust custom DAW stackMaximum direct control over native modules.We must own the sequencer, DSP graph, plugin host, compensation and many editor semantics.Do not make language purity the acceptance criterion.

The Tauri WebView varies by OS: WKWebView on macOS, WebView2 on Windows and WebKitGTK on Linux. Electron offers a controlled Chromium version. Test pointer capture, IME, accessibility, drag/drop, long timelines, graphics features and native window focus on each supported platform. [S1] [S12]

Audio engine choice remains a separate decision

CPAL provides audio I/O, not Logic-like scheduling, editing or plugin compatibility. Tracktion is a higher-level sequenced-audio engine written in C++. Evaluate the latter behind a narrow native adapter before committing to rebuilding those capabilities. [S6] [S7] Tracktion and JUCE have separate licensing requirements; resolve them before adoption. [S6]

Prototype plugin discovery and native editor windows in the foundation phase, rather than discovering an incompatible host surface after implementing the full mixer. FFI bindings, native event-loop affinity, ownership and crash behavior need explicit tests.

Isolation is not automatic security

Tauri capabilities restrict frontend access, but do not sandbox arbitrary Rust, native plugins or AI-generated programs. [S10] Keep plugin and AI workers separate from privileged project services. Grant only required file/device access; apply platform sandbox controls where feasible. Do not execute arbitrary generated JavaScript in the privileged editor.

Use a data-oriented visual scene schema or a restricted shader pipeline with validation, compilation isolation and workload limits. GPU processes can still compete for shared hardware; worker separation does not eliminate GPU contention.

Native graphics integration is its own prototype

Start with an independent native output window and a reduced-rate editor preview. Do not assume a wgpu renderer embeds into a WebView as a zero-copy canvas. Test compositing, multi-monitor output, resizing, color and clock alignment. Defer camera-hand tracking behind touch/MIDI unless its end-to-end latency and permissions meet the same input contract.

05 / MIGRATION SEQUENCE

Move the boundary before expanding the features.

Freeze contracts and baseline

Record the audited commit, preserve the parity inventory, define document ownership and establish reproducible audio fixtures. Do not treat interfaces as completed features.

Prove Tauri and a native engine together

Run one audio track and one instrument outside the WebView. Open a native plugin editor. Reload the UI while audio continues. Exercise device permissions, project selection and process failure recovery.

Port domain ownership—not every UI file

Replace Electron/preload APIs with typed Rust commands. Move authoritative models and validation to shell-independent Rust crates. Keep React/TypeScript; replace placeholder controls with accessible working behavior.

Complete one real studio workflow

Import and record → arrange → instrument → mix → undo → save → reopen → export. Add durable asset references, migrations and crash recovery. Then integrate predictive proposals and generation.

Expand under measured budgets

Add plugin coverage, MIDI/gestures, richer editing and native visuals. Retire Electron only after the required gates pass. Do not maintain two production shells indefinitely.

06 / ACCEPTANCE GATES

Approve with measurements—not framework branding.

These are proposed test conditions, not achieved results. Pin hardware, OS, driver, plugin versions and project fixtures before setting a shipping support level.

GateTest designPass condition
G1 · Audio independenceRun the same deterministic native graph with the UI visible, heavily scrolling, reloading and temporarily unresponsive.No UI-induced loss of playback; state reattaches correctly after reload.
G2 · Deadline / I/OSweep 64/128/256-frame buffers at 48 kHz on selected reference devices; playback and recording concurrently.Document supported workload at each buffer size, missed deadlines, callback tail times and measured input-to-output latency.
G3 · Workload headroomBaseline: 64 stereo playback tracks and 8 mono record inputs, defined stock effects; repeat with AI and visuals active.No underruns at the declared supported setting during a 30-minute run. If overloaded, reduce AI/visual work first; report every exception.
G4 · PluginsScan known test plugins; exercise native editor focus/resize, state reload, automation and a deliberately failed worker.Other tracks remain usable; defined bypass/mute fallback, no host-wide crash; compensation includes bridge delay.
G5 · Durable projectCrash during save/record; reopen; undo accepted AI edits; repeat offline render for deterministic nodes.No corrupt prior committed project. Recover the promised journal window. Export matches its defined deterministic reference.
G6 · Platform surfacesTest editor interaction, native plugin windows, graphics output and permissions on macOS first; qualify Windows/Linux separately.No unresolved critical blocker on a declared supported platform. No extrapolation from a single OS.
G7 · Resource and securityMeasure entire process-tree memory, CPU, GPU memory, startup, asset access and hostile worker requests.Bounded job queues; enforce scopes; no arbitrary frontend shell access. Publish shell comparison only with equivalent workloads.

Derived block durations at 48 kHz: 64 frames = 1.333 ms; 128 = 2.667 ms; 256 = 5.333 ms. These are not end-to-end latency promises. Input/output buffering, converters, scheduling and plugin processing add to the measured path.

Final decision: recommend changing VOID to Tauri + Rust now, retaining TypeScript for the interface and selecting the audio backend by proof. The native engine is mandatory for this proposed production architecture; Rust-only dependencies are not.
