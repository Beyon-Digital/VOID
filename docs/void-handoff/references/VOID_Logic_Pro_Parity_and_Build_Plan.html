Repository findings

The existing code is small enough that the dominant gap is absent implementation. These findings distinguish concrete defects from capabilities that have simply not been built.

FND-01 / Blocker

The desktop entrypoint is a shell

Renderer mounts a heading, a fixed-value knob, a fixed-value fader and a ping result. It does not mount the SessionView or wire an audio workflow.

Action: Keep the shell; replace the demo root with a document-backed workspace and the F1 vertical slice.

R01
FND-02 / Blocker

Audio methods largely do nothing

Recording, BPM, loop, track mixing/routing and clip edits are empty. Current beat is always zero. Track/node factories do not build a signal graph.

Action: Do not add more feature UI on these stubs. Establish the engine adapter and integration tests first.

R02
FND-03 / Blocker

Meters are placeholders

The adapter returns cached, unfilled arrays and constant zero peak/RMS values. Allocation optimization is not measurement implementation.

Action: Connect real analysis streams with explicit units and UI-rate throttling.

R02
FND-04 / High

The controls are not interactive

Knob and Fader accept onChange but never call it. Neither contains pointer/keyboard input behavior. The renderer also provides no update handlers.

Action: Implement a shared parameter-control primitive with value bounds, focus, keyboard and gesture transactions.

R10 R11 R01
FND-05 / High

Scene membership is encoded in ID prefixes

SessionClip has no sceneId. SessionView chooses a scene from clip.id prefixes, rather than an explicit track×scene slot.

Action: Introduce SceneSlot; migrate any sample data; test arbitrary UUIDs, empty cells and prefix collisions.

R04 R05
FND-06 / Blocker

No persistent musical document

The domain lacks asset references, note events, tempo maps, takes, processor state, revisions and undo. ProjectPort only declares three methods.

Action: Define the canonical project aggregate and its journal before AI, mixer or arrangement features are parallelized.

R03 R09 R20
FND-07 / Blocker

AI and visuals are contracts, not integrations

AIPort and VisualPort declare generation, memory and shader operations. The inspected tree contains no matching provider, model manager or visual renderer.

Action: Implement jobs, capability policies, preview/accept and durable provenance. Do not count model names in comments as integrations.

R06 R07 R20 R19
FND-08 / High

The extension model is not a native plugin host

PluginPort describes a WASM manifest and registration methods. It is not an AU, VST3 or CLAP implementation.

Action: Separate native hosting from untrusted WASM devices, and test discovery/state/latency/crashes explicitly.

R08 R20
FND-09 / Blocker

The quality gate is not in place

void-core test script explicitly prints "Error: no test specified" and exits 1. No CI workflow directory or automated test files were found in the inspected trees.

Action: Add real unit/integration/DSP tests and bounded CI jobs. No build, hardware or runtime pass is claimed by this audit.

R14 R22 R19 R20
FND-10 / High

README and migration plan overstate implemented scope

README describes multiple absent packages and a large Ableton-style feature set. Migration planning prioritizes that scope, rather than current Logic parity.

Action: Replace implementation claims with an evidence-backed status ledger and the sequence in this report.

R17 R18 R19 R20 R21
FND-11 / Design gate

Electron starts with useful isolation defaults

The window explicitly disables nodeIntegration and enables contextIsolation; the only current IPC operation is ping. This is not evidence of an exploitable AI surface today.

Action: Before adding jobs/files/plugins, enforce origin/sender checks, narrow IPC, permission handlers, CSP and untrusted-content isolation.

R12 T03
FND-12 / Design gate

AI action and time contracts need stronger types

Copilot actions are arbitrary records; generation has little musical context; arrangement markers use an unspecified time unit; separation declares only four stems.

Action: Use typed, revision-bound proposals with ticks/samples, capability negotiation, cancellation and immutable outputs.

Proposed product behavior

What composing in VOID should feel like

One song, many input methods. Mouse, keyboard, MIDI, touch, gestures and AI all edit the same notes, clips, device parameters and automation. A generated asset is a normal asset. A suggested phrase is a normal editable phrase after acceptance. Turning AI off must never disable the studio.

1. Predictive autocomplete is musical, not just conversational

3. Generate the missing part—not an opaque replacement for the song

Symbolic music lane

Fast, constrained notes/chords/patterns and accompaniment. Start with reliable rule-based suggestions, then add small task-specific models. The result stays editable MIDI. Do not make a general chat model responsible for sample timing.

Audio asset lane

One-shots, loops, sound effects, stems, continuation and inpainting run as cancellable jobs. Crop, align and audition the result before insertion. Preserve original recordings and protected regions. Do not promise perfect stem isolation or full MIDI recovery from arbitrary mixes.

Model selection gate: the repository names ACE-Step and Demucs in comments, but has no corresponding implementation. Keep them as candidates, not adopted production dependencies. Evaluate every candidate against task quality, editability, commercial terms for code and weights, supported languages/instruments, duration limits, device memory, latency and output provenance. A four-stem separator does not satisfy six-stem coverage. R06 A12

4. Conventional and generated visuals share a real timeline

Use normal image/video clips, authored visual presets and generated assets in the same layer model. Expose trim, fade, opacity, transforms, blend modes, scene transitions and audio-feature mappings. Provide preview and separate program output. Freeze expensive video/shader work before performance; late generation must never delay a musical cue. Renderer process isolation cannot guarantee immunity from a GPU-driver or operating-system fault; retain a lightweight fallback and qualify each supported hardware path.

A practical journey is: record or draw a phrase → audition a continuation → edit notes → build the arrangement → choose or generate visuals → rehearse → export music or an audiovisual performance. Each step has a manual path, undo and saved state.

Command and generation lifecycle

UI / controller / AI proposal
    → validate schema, capability, target IDs and expected revision
    → preview / audition (no persistent mutation)
    → user acceptance where required
    → atomic project transaction + undo record
    → deterministic engine projection + acknowledged revision
    → autosave/journal outside the audio callback

GenerationJob
    queued → preparing → running → validating → ready for audition
                     ↘ cancelled / failed / resource-limited
    ready → accepted (new asset + one transaction) OR discarded
    base revision changed → revalidate or mark stale; never silently apply

Live performance parameters
    bounded timestamped input → real-time queue → smoothed parameter
    optional automation recording → one consolidated edit transaction

Realtime and offline data must not be confused. A live gesture can change a bounded parameter immediately. A model-generated four-bar continuation is prepared ahead of time and queued at a musical boundary. A cloud response is never awaited by the audio clock.
